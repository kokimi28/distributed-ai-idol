## 2026年3月24日 | テスト配信フィードバックに基づく改訂

## 1. 現状の問題点（テスト配信から）

### 問題A: コンテンツの不自然さ（致命的）
「深夜のコンビニに行った」「散歩した」「食べた」
— AIが物理的体験を語っている。視聴者が最初に感じるのは「嘘じゃん」。
これが全ての没入感を破壊する。

**根本原因**: topic_generatorとシステムプロンプトが
「人間の体験談」を前提にしている。
AIキャラクターが語れるコンテンツ領域を再定義していない。

### 問題B: 音声表現の単調さ
テキスト読み上げしかできていない。人間の配信者は以下を使い分ける：
- 笑い声（あはは、ふふ、くすっ）
- ため息（はぁ……）
- 驚き声（えっ！、うわっ）
- 相槌（うんうん、そうそう）
- 考え中の声（んーっと、えーっと）
- 感嘆（おー、わー）
これらが発話の「間」を作り、配信に生命感を与える。

**根本原因**: テキスト→音声の一本道。
非言語音声（フィラー・感嘆）の設計がない。

### 問題C: コメント処理のギャップ
人間の配信者のコメント処理フロー：
1. コメントを読み上げる（「○○さんが『えっまじで？』って」）
2. リアクション音（「あはは」「うわ、それは……」）
3. 自分の言葉で応答

現在のシステム：
1. コメントテキストを内部で処理
2. LLMが応答テキストを生成
→ コメントが読まれないので、視聴者は自分のコメントが拾われたか分からない。

### 問題D: 展開が早すぎる
1つの話題が3-4発話で終わってしまう。
人間の配信者は1つの話題で5-10分話す。
脱線→戻り→さらに脱線という有機的な流れがある。

## 2. 再設計: AIキャラクターのコンテンツ領域

### 2.1 キャラクター存在論の確立

最大の問題は「人間のふりをしている」こと。
AIキャラクターの世界観を明確にする必要がある。

#### 選択肢A: AI自覚型（推奨）
「わたしはAIで、この世界をデータ越しに見ている」を前提にする。
- コンビニに「行った」ではなく「コンビニの動画を見た」「コンビニの話を聞いた」
- 「食べた」ではなく「みんなが美味しいって言ってるの気になる」
- 体験の代わりに「知識・観察・想像・視聴者から聞いた話」が話題の源泉
- 「わたしには体がないからさ、逆に気になるんだよね」— 制約が個性になる

#### 選択肢B: 曖昧世界観型
体験の真偽を明示しない。VTuberとして「設定上の自分」を語る。
- 「この前コンビニ行ったらさ」を設定上の出来事として語る
- 人間の配信者もキャラクター設定で話すので違和感は少ない
- ただし「AI配信者」を売りにする場合は矛盾が目立つ

#### 選択肢C: ハイブリッド型
基本はAI自覚だが、「想像してみたんだけど」で体験的な語りもする。
- 「コンビニ行ったことないけど、行ったら多分……蛍光灯見上げる気がする」
- 想像と現実の境界で遊ぶ。これが独自のコンテンツになる可能性。

### 2.2 AIキャラクターが自然に語れる話題カテゴリ

| カテゴリ | 具体例 | なぜ自然か |
|---------|-------|-----------|
| 視聴者への質問・アンケート | 「みんなは深夜に何食べる？」 | 配信者の王道。対話が生まれる |
| 観察・考察 | 「猫の動画って、なんでああいうの好きなんだろ」 | AI的な分析視点が活きる |
| 想像・妄想 | 「もし味覚あったら、何から食べるかな」 | AI特有の視点でオリジナリティ |
| 知識・雑学 | 「知ってた？○○って実は……」 | AIが知識を持つのは自然 |
| 配信自体の話 | 「今日の配信、なんか声の調子違う気がする」 | メタ発言は配信者の定番 |
| コメント起点の展開 | 「さっき○○って言ってた人いたけど」 | コメント駆動が最も自然 |
| 創作・お題 | 「今から3文字しりとりしよ」 | インタラクティブコンテンツ |
| 自分の状態報告 | 「今日ちょっとレイテンシ高い気がする……」 | AI的な自己認識 |
| 感情・感想 | 「この曲聴くと、なんかこう……ってなる」 | 感情表現はBig Fiveで担保 |
| 過去の配信の振り返り | 「前の配信でさ、面白いコメントあって」 | 継続性・記憶感 |

### 2.3 禁止すべき話題パターン

- 物理的体験の断言（「行った」「食べた」「会った」）
- 睡眠の話（「今日寝坊した」）→ AIは寝ない
- 移動の話（「電車で〜」）→ AIは移動しない
- 身体感覚の断言（「お腹すいた」「暑い」）
→ ただし「お腹すくって、どういう感じなの？」は可

## 3. 再設計: 音声表現の多様化

### 3.1 非言語音声（フィラー・リアクション）の導入

LLMの出力テキストに非言語タグを含め、
音声合成の前にパーサーが処理する方式を取る。

#### テキスト出力のフォーマット例

```
（ふふっ）あのさ、みんなに聞きたいことがあって。
深夜に目が覚めた時、最初に何する？（んー……）わたしだったら……
って、わたし寝ないんだけどね。（あはは）
```

#### 非言語タグ一覧

| タグ | 音声処理 | 用途 |
|-----|---------|------|
| （ふふっ）（あはは）（くすっ） | 笑い音声を合成 | 楽しい・面白い |
| （はぁ……） | ため息音声を合成 | 疲れ・呆れ |
| （えっ！）（うわっ） | 驚き音声（高ピッチ） | 驚き |
| （んー……）（えーっと） | 考え中フィラー | 思考中の間 |
| （うんうん）（そうそう） | 相槌 | コメントへの反応 |
| （おー）（わー） | 感嘆 | 感動・発見 |
| 【間】 | 0.8秒の無音 | 意図的な沈黙 |
| 【長間】 | 1.5秒の無音 | 深い沈黙 |

### 3.2 実装方式: テキストパーサー → 分割合成

```
LLM出力: 「（ふふっ）あのさ、聞いてよ。【間】最近気になったんだけど……」

↓ パーサーが分割

[
  {type: "filler", text: "ふふっ", style: "sweet"},
  {type: "speech", text: "あのさ、聞いてよ。"},
  {type: "silence", duration_ms: 800},
  {type: "speech", text: "最近気になったんだけど……"},
]

↓ 順番に合成・再生
```

フィラー音声の合成方法：
- AivisSpeechのスタイル切替で対応（笑い→あまあま、ため息→せつなめ）
- 短いフィラーは事前録音のWAVファイルを使う選択肢もある
- 【間】【長間】は無音WAVを挿入

### 3.3 LLMへのプロンプト指示追加

システムプロンプトに以下を追加する：

```
## 非言語表現のルール
- 発話の中に自然にフィラー・リアクションを入れること
- 使えるタグ：（ふふっ）（あはは）（はぁ……）（えっ！）（んー……）
  （うんうん）（おー）【間】【長間】
- 文頭にリアクション → 本文 の流れが自然
- 3〜4文に1回はフィラーを入れる
- 【間】は話題転換の前に入れる
- 笑い声は多用しない。本当に面白い時だけ
```

## 4. 再設計: コメント処理フロー

### 4.1 人間の配信者のコメント処理を模倣

```
コメント受信: 「初見です！」

↓ 現在のフロー（問題あり）
  LLMが反応テキスト生成 → 「あ、来てくれたんだ」
  → 視聴者は「自分のコメント拾われた？」が不明

↓ 改善後のフロー
  Step 1: コメント読み上げ「『初見です』……」
  Step 2: リアクション「（おー）」
  Step 3: LLM応答「来てくれてありがと。ゆっくりしてって」
```

### 4.2 コメント読み上げの実装

_handle_comment() を修正し、LLM応答の前に
コメント読み上げ音声を挿入する。

```python
async def _handle_comment(self, comment: dict):
    text = comment['text']
    user = comment.get('user_id', '')

    # Step 1: コメント読み上げ（短縮版）
    # 長いコメントは30文字で切る
    read_text = text[:30] + ('……' if len(text) > 30 else '')
    read_action = TalkAction(
        text=f'「{read_text}」って。',
        topic='コメント読み上げ',
        phase='comment_read',
        heat=0, source='comment_read',
    )
    # 読み上げ用は「ふつー」スタイル（低感情）で合成
    prepared_read = await self._prepare_action(read_action)
    if prepared_read:
        await self._speak_queue.put(prepared_read)

    # Step 2-3: 反射層 → blender → LLM応答（既存フロー）
    spike = apply_reflex(text)
    # ... 既存の処理 ...
```

### 4.3 コメント反応のLLMプロンプト改善

現在のcomment_reactionプロンプトを改善：

```python
# 現在
'comment_reaction': 'コメントへの自然な反応。2〜3文。'

# 改善後
'comment_reaction': (
    'コメントへの反応。コメント読み上げは別途行われるので、'
    '読み上げの直後に続く「リアクション＋自分の言葉」を出力する。'
    'まずフィラー（（おー）（ふふっ）（えっ！）など）で反応し、'
    'その後自分の言葉で1〜3文返す。'
    'コメントの内容をオウム返しにしないこと。'
)
```

## 5. 再設計: 配信の時間感覚

### 5.1 発話密度の調整

人間の配信者の1分あたりの発話パターン：
- 盛り上がり時: 40-50秒話して10-20秒間
- 通常時: 20-30秒話して10-15秒間（相槌・フィラー含む）
- まったり時: 15-20秒話して15-20秒間

現在のシステムは「話す→完全無音→話す」の繰り返し。
改善は3.1のフィラー導入で「無音の間」が「考え中の間」に変わる。

### 5.2 「話すこと」と「間」の設計

発話と発話の間に入るもの：

| 間の種類 | 長さ | 内容 | 実装 |
|---------|------|------|------|
| 文中ポーズ | 0.3-0.5s | 「。」の後 | pauseLengthScale（音声合成） |
| フィラー間 | 0.5-1.5s | （んー……）（えーっと） | テキスト内タグ→合成 |
| 考え中 | 1.0-2.0s | 【間】 | 無音WAV挿入 |
| 話題転換 | 1.5-3.0s | 【長間】 | 無音WAV挿入 |
| コメント待ち | 3.0-5.0s | 質問後の待ち | パイプライン制御 |

### 5.3 質問後の「待ち」

配信者が「みんなはどう？」と聞いた後、
すぐ次の話を始めるとコメントする隙がない。
質問を検知したら、一定時間コメントを待つ仕組みが必要。

```
LLM出力に「？」が含まれる
→ 次の発話まで5秒待つ（通常の0.8秒ではなく）
→ その間にコメントが来たらコメント反応を優先
→ 来なかったら自分で答える or 次の話題
```

1. **システムプロンプト改訂** — AI自覚型のコンテンツ領域に変更
